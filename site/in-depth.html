Principle

Never invert audio into a location. Instead, for every candidate location and every recording start time, predict the signal the recording would contain from logged events (lightning flashes, ADS-B tracks), score the prediction against the recording, and rank. The unknown start time plays the role of a GPS receiver's clock bias. The spacing between events constrains the position, and the geometry of the sources sets the shape of the uncertainty: sources in one direction give a ridge, not a point.

Internally everything is SI and UTC. Geometry runs in ECEF with WGS84 heights. Aircraft use geometric (GNSS) altitude where broadcast, and barometric altitude shifted by each leg's median geometric-minus-barometric offset elsewhere. Ground height is Copernicus GLO-30 plus the EGM96 geoid undulation, so aircraft and ground share the ellipsoid.

Thunder

Observed envelope

Decode to mono, resample to 2 kHz, zero-phase Butterworth band-pass 20 to 250 Hz, RMS over 0.25 s frames, Gaussian smoothing (about 5 s), subtract the 10th-percentile floor, and resample to the sweep step. A heuristic wind flag (20 to 60 Hz dominating 60 to 250 Hz) can mask frames.

Forward model

For flash i at horizontal distance dh, source height h = 2,000 m and sound speed c = 343 m/s:

tarr,i = tflash,i + √(dh² + h²) / c

Loudness falls off with distance r as a power p = 2 with a near-field cap, so close strikes saturate like a clipped microphone:

Ai = (rnear / max(ri, rnear))p

Each flash is rendered as a fast-attack, slow-decay pulse whose decay grows with distance (distant thunder rumbles longer), and the sum is smoothed like the observed side:

k(t) = (1 − e−t/rise) · e−t/decay,   m(t) = Σi Ai k(t − tarr,i)

Score

Sliding cosine similarity over every start offset τ, with the model energy taken only inside the clip-length window L:

s(τ) = Σt o(t) m(t + τ) / ( ‖o‖ · ‖m[τ, τ+L]‖ )

The numerator for all offsets is one FFT cross-correlation per batch of 256 candidates, and the denominator a cumulative sum of m², so each candidate costs O(n log n). The Pearson option removes the mean of each window first, so a continuous rumble shared by many places earns no credit.

Search

  1. Candidate grid at 5 km, land only (Natural Earth), inside the region prior.
  2. Prefilter: keep points with at least N flashes within 25 km in some clip-length window, N = max(3, round(0.6 × observed peak count)).
  3. Coarse pass at a 5 s step over the whole time prior.
  4. Refine the best regions (greedy, at least 15 km apart) on a 1 km grid within 5 km at 1 s, then on a 200 m grid within 1 km, staying inside the time prior.

A continental-US day (682,694 flashes, 80,475 candidates after the prefilter, 17,281 offsets) runs in 114 s on one core. GLM places flashes to about 3 to 4 km, which is 9 to 12 s of acoustic timing: in a dense storm the model can't tell which flash made which clap.

Aircraft Doppler

Measuring a flyover

The spectrogram uses a long window for frequency resolution and is whitened per frequency (dB above that frequency's median), so faint lines show and filters cancel out. Each flyover is traced in the app and fitted with the straight, constant-speed model, with emission time te and reception time tr:

r(te) = √(d² + v²(te − t0)²),   vr = v²(te − t0) / r(te),   tr = te + r(te) / c
f(tr) = f0 · c / (c + vr(te))

Worked example from the unit tests: f0 = 130 Hz at vr = −57.97 m/s gives 156.44 Hz. Measurements are stored as ranges, not points. A trace without the curve's far wings fixes only v²/d, so the fit profiles the speed: it holds v at 28 values from 15 to 300 m/s, refits the rest, and keeps every row within 0.5 Hz rms of the best. The search then narrows distance, fundamental and timing to each real flight's own speed.

Exact model

For a candidate observer o and the real track p(t), interpolated to 1 s, the emission time is found by fixed-point iteration, which converges in 3 to 5 steps because v ≪ c:

te = tr − ‖p(te) − o‖ / c,   vr = ṗ(te) · (p(te) − o) / ‖p(te) − o‖

Using the aircraft's position at reception time instead gives a differently shaped curve, not just a delayed one; a unit test checks that.

Funnel

  1. Flights: piston and turboprop types (ICAO description letter P or T) and unknowns; jets and helicopters are dropped.
  2. Speed gate: samples whose speed fits the event's profile.
  3. Pair prefilter: each sample implies a recording start for each event, were the closest approach there. Samples of two flights are matched in position and implied start, which keeps the search to pairs that meet in space in the right time order.
  4. Distance tube: 200 m cells where the closest-approach slant distance fits the event at that flight's speed, using terrain. Each cell walks along the track to the closest approach of its own pass, because aircraft in a traffic pattern pass the same spot several times.
  5. Timing: both events must imply the same start, within tolerance; with a clock, the start must also match it.
  6. Silence: drop (hard) or penalize by 3 dB per flight (soft) candidates that would have heard another flight within 4 km while the recording was silent.

Score and refine

The score is the whitened brightness along each modeled curve, averaged over a 60 s window either side of the heard closest approach, with frames weighted by (closest slant / slant) so the loud, steep part decides. Frames the track doesn't cover count as zero with full weight: a leg must explain the whole flyover, not just its brightest seconds. Harmonics are averaged with weights 1/n. Event 1 sweeps a small time shift and f0; event 2 sweeps f0 only, because its timing relative to event 1 is fixed by the geometry. The best cell of each top flight pair is refined at 100 m within 300 m, then at 25 m within 100 m.

One straight flyover is mirror-symmetric across its ground track, so a single event with a clock gives the site and its reflection. Track curvature, terrain, silence or a second event break the tie.

What real recordings taught

Every M6 failure turned out to be a measurement or convention problem, found by scoring the true site by hand with the true flights:

  • Heard crossing, not closest approach. The fit reported when the plane was nearest; the search expects when that sound arrived, d/c later. For a 6 km flyover that is 18 s, which put the modeled curve 18 Hz off the line.
  • Honest speed ranges. A faint trace fitted 60 to 230 m/s equally well while the fit claimed ±2.7 m/s. The true aircraft flew 104 m/s and was excluded until the fit profiled the speed.
  • Passes. Pattern traffic passes a spot every few minutes, and only one pass was heard; the funnel now resolves each pass.
  • Clocks. A known start was first treated as an alternative to a second event. Used together, they located the phone video that each failed alone.

Reproduce

earwitness demo                                   # install check, offline
uv run python scripts/m2_acceptance.py ...        # thunder acceptance (VALIDATION.md has the flags)
uv run python scripts/m4_acceptance.py ...        # aircraft acceptance
uv run python scripts/m7_countermeasures.py       # filters, codecs and cuts on the demo cases

Every analysis writes a run folder with its priors, events, configuration, results, heat map and log, so any result can be rerun from its folder. Real-recording truths stay in private files and are read only when scoring.
